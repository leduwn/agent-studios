## 1. Executive Summary & Binary Roles

`[ASSISTANT_OR_CLAUDE_PROPOSAL]`
Agent Studios provides two complementary native binaries:
1. **`agsd` (Agent Studios Daemon)**: The headless, background system service hosting the Control Plane actor, SQLite WAL database, Git worktree manager, IPC transport listener (Named Pipe / UDS), and runtime execution engines.
2. **`ags` (Agent Studios CLI & TUI)**: The primary command-line tool and terminal user interface for developers and automated CI pipelines. It functions as a lightweight client connecting to `agsd` via native IPC.

```text
┌────────────────────────────────────────────────────────┐
│                   CLI / TUI INVOCATIONS                │
│       ags run "Goal"  │  ags tui  │  ags provider ls   │
└───────────────────────────┬────────────────────────────┘
                            │ Native IPC (Named Pipe / UDS)
                            ▼
┌────────────────────────────────────────────────────────┐
│                  NATIVE AGSD DAEMON                    │
│     (Control Plane, Worktrees, Runtimes, Providers)    │
└────────────────────────────────────────────────────────┘
```

## 2. Invocation Modes

The `ags` binary operates in three distinct execution modes:

### 2.1 Interactive Terminal UI (TUI) Mode (`ags` or `ags tui`)
- Launches a rich, full-screen terminal interface built with Ratatui and crossterm.
- Designed for keyboard-centric developers who prefer a terminal-based workflow without opening VS Code.
- Provides real-time streaming, task graph visualization, interactive approvals, and diff inspection.

### 2.2 Direct Command & Inspection Mode (`ags <subcommand>`)
- Rapid CLI interactions for listing tasks, inspecting agent states, reviewing diffs, or granting approvals.
- Formatted with human-readable tables, color-coded badges, and optional `--json` machine output.

### 2.3 Headless Automation Mode (`ags run --headless`)
- Designed for CI/CD pipelines, pre-commit hooks, and unattended build scripts.
- Streams newline-delimited JSON (NDJSON) events to stdout.
- Evaluates exit codes deterministically (0 = success, non-zero = failure).
- Strictly non-interactive; fails closed if an unapproved critical action is encountered.

## 3. Comprehensive Command Tree

```text
ags [OPTIONS] <COMMAND>

COMMANDS:
  init          Initialize an Agent Studios workspace in the current directory
  run           Execute a high-level goal using multi-agent orchestration
  tui           Launch the full-screen interactive Terminal User Interface
  session       Manage and inspect active or historical sessions
  task          Inspect task status, dependencies, and execution logs
  approve       Approve a pending action or tool execution request
  deny          Deny a pending action or tool execution request
  diff          Inspect reconciled binary or text diffs generated by workers
  provider      Manage, configure, and discover LLM provider instances
  daemon        Manage the local agsd background service lifecycle
  config        View or modify local Agent Studios configuration
  version       Display version, commit SHA, and platform target details

OPTIONS:
  -c, --config <PATH>      Path to custom configuration file
  -s, --session <UUID>     Target specific session ID (defaults to active)
  --json                   Output responses in structured JSON format
  -v, --verbose            Enable detailed debug tracing
  -h, --help               Print help information
```

### Detailed Subcommand Breakdown

#### 3.1 `ags run`
```bash
ags run [OPTIONS] "<GOAL>"

OPTIONS:
  -m, --model <PROVIDER:MODEL>  Specify model target (e.g. anthropic:claude-3-7-sonnet)
  --headless                    Run in non-interactive CI automation mode
  --timeout <SECONDS>           Set hard execution timeout budget (default: 1800s)
  --max-tokens <COUNT>          Set pre-execution token budget limit
  --auto-approve <TIER>         Auto-approve actions up to risk tier (low|medium)
```

#### 3.2 `ags provider` (Incorporating PR #20 Dynamic Discovery)
```bash
ags provider list                      # List configured provider instances
ags provider add <TYPE> --name <NAME>  # Add provider (openai|anthropic|gemini|ollama)
ags provider test <NAME>               # Validate connection and measure latency
ags provider discover <NAME>           # Dynamically discover available remote models
```
*Note*: `ags provider discover` integrates the HTTP wiremock-tested `ModelDiscoveryClient` implemented in PR #20 (`feat/provider-management-v1`), querying remote `/v1/models` endpoints dynamically.

#### 3.3 `ags daemon`
```bash
ags daemon start    # Spawn agsd background process if not running
ags daemon status   # Check daemon PID, socket path, uptime, and active sessions
ags daemon stop     # Gracefully terminate the running agsd daemon
ags daemon logs     # Tail native daemon event log
```

### Keyboard Navigation & Shortcuts
- `Tab` / `Shift+Tab`: Cycle active focus across panels (Tasks, Stream, Input).
- `Up` / `Down` or `j` / `k`: Navigate task list, diff viewer, or message history.
- `Enter`: Submit prompt or select focused item.
- `a`: Quick-approve pending action.
- `d`: Quick-deny pending action.
- `v`: Open full-screen diff review popup.
- `q` or `Ctrl+C`: Exit TUI (daemon continues running uninterrupted).

## 5. Headless Automation & CI/CD Invariants

For automated pipelines (`ags run --headless "<goal>"`):
1. **Deterministic Exit Codes**:
   - `0`: Goal completed, all tasks `Succeeded`, all automated tests passed.
   - `1`: Task execution failure (compiler error, test failure).
   - `2`: Approval blocked (unattended script encountered a High/Critical action without `--auto-approve`).
   - `3`: IPC or daemon connection failure.
2. **Machine-Readable Stream**:
   - Every state transition emits a JSON line to stdout matching the `RuntimeEvent` schema.
   - Diagnostic and error traces output to stderr to prevent corrupting stdout pipes.
3. **Zero Token Leakage**:
   - Telemetry output scrubs all sensitive environment variables and credentials before terminal emission.
