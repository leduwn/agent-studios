# Milestone M15 UI-01.1 Review: Streaming Lifecycle Verification

**Component**: `TaskExecutionStore.ts` & `ChatHtmlBuilder.ts`  
**State Model**: Live Reactive Execution Projection  

---

## 1. Truthful Status Progression

Task lifecycle does not fabricate immediate execution or success:

```
[idle] ──(beginSubmission)──> [submitting] ──(taskSubmitted)──> [queued]
                                                                   │
                                                            (task_started /
                                                         run_started / state_transition)
                                                                   │
                                                                   v
                                                               [running]
                                                                   │
                              ┌────────────────────────────────────┼─────────────────────────────────┐
                              │ (task_completed / run_completed)  │ (task_failed / run_failed)      │ (task_cancelled)
                              v                                    v                                 v
                         [succeeded]                            [failed]                        [cancelled]
```

### Invariants Verified
1. **Queued State**: `taskSubmitted(taskId, studioId)` sets status to `'queued'`. It does NOT assume the agent runtime has immediately spawned or obtained daemon locks.
2. **Authoritative Execution Transition**: The transition from `'queued'` to `'running'` occurs ONLY when the daemon emits authoritative events:
   - `task_started`
   - `run_started`
   - `task_state_transitioned` with `to_state: 'running'` or `'executing'`
   - `run_state_transitioned` with `to_state: 'running'` or `'executing'`
3. **No Completion by Inference**: Closing an event stream, receiving an empty chunk, or socket disconnect never transitions a task to `'succeeded'`. Completion requires explicit `task_completed` or `run_completed` events.

---

## 2. Real-Time Streaming & Tool Activity Tracking

1. **Streaming Output Deltas**:
   - `runtime_output_delta` and `output_delta` events append text chunks directly via `payload.text`, `payload.output`, or `payload.chunk`.
   - Streaming console updates incrementally via `onDidStreamChunk` and DOM appending without resetting scroll position.
2. **Tool Execution Monitoring**:
   - `tool_started` / `tool_executing`: sets `activeTool = { name, status: 'executing', timestamp }`.
   - `tool_completed`: updates status to `'completed'`.
   - `tool_failed`: updates status to `'failed'` and captures `error`.
   - Active tool banner in UI displays live spinner, tool name, and error banner if failed.

---

## 3. Truthful Telemetry & Zero Fabrication Policy

- `ExecutionMetrics.isReported` defaults to `false`.
- If metrics are unreported, the UI explicitly shows: `Metrics: Pending daemon telemetry`.
- When daemon emits telemetry in event payloads (`prompt_tokens`, `completion_tokens`, `total_tokens`, `cost_usd`, `latency_ms`), `updateMetrics` sets `isReported: true`.
- Tokens are formatted with locale-independent delimiters: `totalTokens.toLocaleString('en-US')`.
- Zero synthetic tokens or estimated costs are ever generated by the IDE extension host.
