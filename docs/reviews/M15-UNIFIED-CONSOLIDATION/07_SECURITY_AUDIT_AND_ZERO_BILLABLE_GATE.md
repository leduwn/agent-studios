## 1. Executive Summary

A comprehensive security audit of the unified Agent Studios codebase was conducted across both the backend (`agent-studios-rs`) and frontend (`apps/agent-studios-vscode`) systems.

Key verification findings:
1. **$0.00 Token Invariant Enforced**: At no point during testing, compilation, or daemon operation are billable AI cloud provider APIs invoked. Task execution fails closed unless explicitly permitted by the operator through multi-factor validation.
2. **Credential Scrubbing & Zero Leakage**: All API keys, secrets, and authorization bearer tokens are encrypted in memory (`SecretString`), scrubbed from diagnostic payloads, and redacted in log streams.
3. **Fail-Closed Capability Matrix**: Mutation commands over standard client IPC connections are rejected with permission errors. Operator confirmation challenges require valid cryptographic signatures and reject replay or expiration.
4. **Sandboxed Subprocess Execution**: Subprocesses spawned by runtime adapters are subject to strict OS-level containment:
   - On Windows: Win32 Job Objects configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.
   - On Linux/macOS: Dedicated process groups (`setpgid`) with coordinated `SIGTERM`/`SIGKILL` cascades.
5. **Path Traversal & Workspace Isolation**: Workspace directories and artifact storage reject directory traversal sequences (`..`), junction escapes, and absolute path injection outside designated session directories.

## 2. Zero Billable AI Execution Gate ($0.00 Token Invariant)

To guarantee that automated testing, continuous integration, and local developer runs never incur unwanted cloud API costs, three defense-in-depth layers are active:

### Layer 1: Build-Time & Configuration Gate
- In `crates/provider/src/lib.rs` and `crates/control-plane/src/lib.rs`, model dispatch requires explicit runtime opt-in via environment variables.
- Default configuration disables task dispatch: `task.submit = false` in `CapabilityMatrix`.

### Layer 2: Wire Protocol Fail-Closed Rejection
In `apps/agent-studios-vscode/src/bridge/DaemonConnectedBridge.ts` and `crates/ipc-transport/src/connection.rs`:
- Any `SubmitTask` request received from a standard client connection is immediately rejected if `task.submit` is disabled in the active capability matrix.
- Automated tests mock CLI invocations or execute non-billable inspection commands (`claude --version`, `claude --help`).

### Layer 3: Two-Phase Operator Confirmation Challenge (2PC)
- Submitting an execution task requires an unexpired cryptographic challenge generated by the daemon.
- The extension prompts the operator with a high-risk confirmation modal displaying the exact prompt hash, model target, and workspace directory.
- Forged, mismatched, or expired challenge tokens immediately fail closed without initiating network or process calls.

## 3. Cryptographic Authentication & Anti-Replay Defense

1. **HMAC-SHA256 Challenge-Response Handshake**:
   - Connection to `agsd` requires authenticating with a pre-shared secret key stored in bootstrap files (`agsd.json` for standard clients, `agsd-admin.json` for administrative operations).
   - Handshake employs 32-byte cryptographically secure random nonces (`generate_nonce()`).
   - Timestamps must fall within a 30-second skew window. Nonces are recorded in an in-memory sliding window to prevent replay attacks.
2. **Role-Based Privilege Separation**:
   - Standard clients are strictly restricted to read-only queries (`ListStudios`, `ListTasks`, `GetHealth`, `SubscribeEvents`, `GetTaskDiff`).
   - Destructive mutations (`Shutdown`, `ResetState`, `EvictSession`) are strictly reserved for admin connections authenticated via `agsd-admin.json`.
   - Role-based diagnostic redaction ensures internal database paths and process identifiers are withheld from standard client reports.

## 4. Subprocess Sandboxing & Process Tree Containment

### 4.1 Windows Win32 Job Object Guard (`#[cfg(windows)]`)
`crates/claude-code-runtime/src/sandbox.rs` wraps child processes within a dedicated Win32 Job Object:
```rust
#[cfg(windows)]
pub struct JobObjectGuard {
    job_handle: RawHandle,
}

#[cfg(windows)]
impl JobObjectGuard {
    pub fn new() -> Result<Self, SandboxError> {
        // Creates Job Object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE
        // Guarantees all descendant processes are terminated if the daemon crashes or exits
    }
}
```

### 4.2 Linux & macOS Process Containment
On POSIX platforms, processes are spawned in new process groups via `setpgid(0, 0)`. Termination delivers `SIGTERM` to the entire negative process group `-pgid`, escalating to `SIGKILL` after a 2-second grace period.

## 5. Artifact Security & Path Traversal Prevention

In `crates/workspace/src/lib.rs` and `apps/agent-studios-vscode/src/bridge/ipc/ArtifactClient.ts`:
1. **Canonicalization & Boundary Enforcement**: All file paths accessed for Git diff generation or artifact retrieval are canonicalized against the validated session workspace root. Attempts to access files with `../`, Windows UNC paths (`\\server\share`), or symlink escapes outside the workspace root are rejected with `PathTraversalDetected`.
2. **Cryptographic Chunk Integrity**: Artifact and diff chunks carry individual SHA-256 digests and incremental byte offsets. Chunks arriving out-of-order or with mismatched digests abort reassembly with `INTEGRITY_FAILED`.
3. **Buffer Limit Protections**: Max IPC frame size is clamped to 4 MiB. Max single artifact size is enforced at 64 MiB to prevent denial-of-service memory exhaustion.
